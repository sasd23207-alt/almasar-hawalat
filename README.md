# المسار للحوالات — حالة التطوير

## الحالة الحالية

**[PARTIAL] تم بناء أساس تطبيق جوال محلي؛ لم يكتمل المنتج المالي النهائي ولم يعتمد للاستخدام الحقيقي.**

### ما تمت إضافته في فرع التطوير
- [WRITTEN-ONLY] واجهة عربية RTL على Flutter مع صفحات الرئيسية والعملاء والعمليات.
- [WRITTEN-ONLY] قاعدة SQLite محلية تحفظ العملاء والأرصدة وسجل العمليات على الجهاز.
- [WRITTEN-ONLY] تسجيل إيداع/استلام أو صرف/إرسال داخل معاملة قاعدة بيانات واحدة، مع منع السحب إذا كان الرصيد غير كافٍ.
- [WRITTEN-ONLY] حفظ المبالغ بوحدات صحيحة صغيرة بدل الأعداد العشرية العائمة، مع دعم LYD بثلاث خانات وUSD/EUR بخانتين.
- [WRITTEN-ONLY] أضيف قفل للتطبيق برقم سري من 6 أرقام محفوظ عبر Android secure storage؛ يلزم نجاح CI واختبار السلوك على جهاز فعلي قبل اعتباره مثبتًا.
- [WRITTEN-ONLY] أضيف تشفير AES-256-GCM للنسخ الاحتياطية مع اشتقاق مفتاح PBKDF2-HMAC-SHA256؛ كلمة مرور النسخة لا تُخزن داخل التطبيق، ويجب حفظها منفصلة. يلزم نجاح الاختبارات قبل اعتباره مثبتًا.
- [WRITTEN-ONLY] ملفات النسخ القديمة غير المشفرة ما زالت مدعومة بعد تحذير صريح للمستخدم.
- [WRITTEN-ONLY] فتح WhatsApp برسالة جاهزة تشمل مرجع العملية، ليقوم الموظف بمراجعتها وإرسالها يدويًا.
- [PARTIAL] يجب انتظار نتيجة CI للنسخة الحالية بعد إضافة القفل والتشفير واختبارات التشفير، ثم اختبار التطبيق على جهاز أندرويد حقيقي.

### ما لا يزال غير مكتمل أو غير مثبت
- [NOT-IMPLEMENTED] ربط WhatsApp Business Platform للإرسال الآلي الرسمي عبر Meta. فتح رابط WhatsApp لا يساوي إرسالًا آليًا.
- [PARTIAL] تحسين استخراج الحوالات يطلب اسم صاحب الحساب واسم التاجر كما يظهران في المحادثة قبل استنتاج الاتجاه؛ أي مرسل غير معروف أو رسالة متعددة المبالغ تبقى للمراجعة. ما زالت هناك حاجة إلى اختبارات ميدانية على عينات حقيقية من صيغ المحادثات.
- [NOT-IMPLEMENTED] نموذج حوالة كامل يتضمن المرسل والمستلم والوجهة وسعر الصرف والعمولة وحالة التسليم والتسوية.
- [PARTIAL] قفل واجهة التطبيق موجود، لكنه ليس تشفيرًا لقاعدة SQLite نفسها. يلزم تشفير قاعدة البيانات على الجهاز قبل اعتمادها لبيانات مالية حساسة.
- [NOT-IMPLEMENTED] مزامنة آمنة بين عدة أجهزة؛ قاعدة البيانات الحالية تخص جهازًا واحدًا.
- [PARTIAL] التحقق المتقدم من اتساق كل رصيد مع دفتر العمليات، ومنع كل حالات التكرار، وسجل تدقيق لا يقبل التعديل.
- [NOT-IMPLEMENTED] اختبارات تكامل فعلية لقاعدة SQLite، واختبار واجهة على جهاز Android حقيقي.
- [NOT-IMPLEMENTED] توقيع إصدار Android ثابت وآمن وتوزيع إصدار إنتاجي.
- [NOT-IMPLEMENTED] تقارير مالية شاملة وتصدير CSV/PDF واستيراد محادثات إن كان ذلك ضمن النطاق المطلوب.

## النسخ الاحتياطي مهم
النسخة الاحتياطية تحتوي بيانات العملاء والعمليات. احفظها في مكان موثوق ولا ترسلها لأشخاص غير مخولين. استعادة النسخة تستبدل السجلات المحلية الحالية؛ خذ نسخة من البيانات الحالية أولًا.

## WhatsApp
الميزة الحالية تفتح محادثة مع رسالة جاهزة للمراجعة والإرسال يدويًا. الإرسال الآلي يتطلب إعداد حساب Meta/WhatsApp Business، ورقمًا مؤهلًا، وقوالب الرسائل اللازمة، وخادمًا آمنًا لحفظ أسرار API؛ لا توضع رموز Meta السرية داخل تطبيق الجوال.

## التحقق عبر GitHub Actions
كل دفع إلى المستودع يشغّل سير العمل. راجع تبويب **Actions** لمعرفة نتيجة كل خطوة؛ لا تعتبر البناء ناجحًا إلا بعد اكتمال جميع الخطوات بنجاح. نجاح التحليل والاختبارات أو بناء APK لا يثبت وحده سلامة التطبيق للاستخدام المالي الحقيقي.

## تشغيل الاختبارات محليًا
بعد تثبيت Flutter:
```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```

## تحذير حول APK التجريبي
سير العمل يبني APK من نوع **debug** وموقّعًا بمفتاح مؤقت. فرع التطوير ينشر الآن إصدارًا تجريبيًا منفصلًا باسم `Test build` بعد نجاح التحليل والاختبارات والبناء. لا تستخدم هذه النسخة لحفظ بيانات مالية حقيقية. قبل التوزيع الفعلي، يلزم استكمال متطلبات الحماية والتدقيق واختبارات الأجهزة والتوقيع الثابت. كل إعادة بناء بمفتاح debug قد لا تسمح بالتحديث فوق النسخة السابقة، وقد يتطلب التثبيت إزالة النسخة القديمة، ما قد يمسح بياناتها المحلية؛ صدّر نسخة احتياطية أولًا.
